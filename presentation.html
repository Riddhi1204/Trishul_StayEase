SECTION 1 & 2
What Problem Are We Solving?
Empowering independent eco-homestay owners and mindful eco-tourists
💸 High OTA Commissions
  • Traditional OTA platforms charge 15% – 25% commission on every booking.
  • Eats away vital income from local, family-owned rural homestays.
  • Forces hosts to inflate rates for eco-conscious guests.
🔍 Fragmented Eco-Discovery
  • Mindful travellers struggle to find verified, authentic sustainable stays.
  • Rampant "greenwashing" makes genuine sustainability hard to verify.
  • Lack of specialized filtering for local nature & cultural activities.
⚡ Complex Direct Booking
  • Small homestays lack digital infrastructure for direct, commission-free reservations.
  • Manual scheduling causes double bookings and lost customer leads.
  • Travellers lack personalized, budget-friendly sustainable itineraries.

SECTION 5
Backend: Top 2 APIs & Implementation
Robust asynchronous endpoints with rate limiting and strict schemas
API 1: POST /api/ai/travel-plan (AI Eco Travel Planner)
  • Purpose: Generates tailored day-by-day sustainable travel itineraries.
  • Mechanism: Accepts destination, budget, days, and style → Checks server TTL cache → Calls Gemini 1.5 Flash with structured schema → Returns validated JSON.
  • Reliability: Robust fallback parser & friendly error toast handling on quota exhaustion.
API 2: POST /auth/register & /auth/login (JWT & OAuth Authentication)
  • Purpose: Enterprise-grade stateless user authentication & dual-role management.
  • Mechanism: Bcrypt password hashing + SlowAPI rate limiting (5 req/15 min) + 24-hour HS256 JWT access tokens + Google OAuth 2.0 SSO verification.
  • Security: Custom HTTP security headers & production CORS middleware.
📖 Live Interactive Swagger API Documentation: https://trishul-stayease.onrender.com/docs
SECTION 6
Database Selection & Schema Design
MongoDB Atlas: Fully managed cloud NoSQL database with async Motor driver
📁 properties Collection
  • id (int, auto-increment PK), title, location
  • price (per night), type (mountain, forest, riverside)
  • status (available, booked), amenities[], images[]
👤 users Collection
  • id (ObjectId PK), full_name, email (Unique Index)
  • phone (Unique), password_hash, role (guest | host)
📅 bookings Collection
  • id (int PK), property_id, guest_id, host_id
  • start_date, end_date, total_price, status
🔢 counters & wishlists
  • counters: Atomic auto-increment sequence generation via $inc.
  • wishlists: Stores guest saved property IDs for zero-friction access.
💡 Rationale: MongoDB's JSON document model effortlessly stores polymorphic amenities & image arrays without relational JOIN overhead.
